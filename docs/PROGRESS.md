跨平台开发策略（v3.3 起执行）
1. 版本号规则
一套代码，一个版本号，两个平台

v3.2.9 代码完整移植到 macOS 后，版本号仍为 v3.2.9

未来新增功能或修复问题，版本号在 main 分支上统一递增（如 v3.3.0）

不同平台的可执行文件版本号相同，仅打包产物不同

2. Git 分支与标签管理
分支：所有开发代码提交到 main 分支，不创建 windows 或 mac 分支

标签：版本标签打在 main 分支上，如 v3.2.9、v3.3.0

平台适配：通过 sys.platform 或 os.name 条件判断在代码中处理

可执行文件：不上传至 Git，通过 GitHub Releases 分发

Windows: CoverPicker_vX.X.X_Windows.zip

macOS: CoverPicker_vX.X.X_macOS.dmg 或 .app.zip

3. 开发与维护工作流
新增功能或修复 Bug：可在 Windows 或 macOS 任一平台上开发

跨平台测试：修改完成后，在另一个平台上拉取最新代码进行兼容性测试

发布流程：

开发完成 → 两个平台分别测试通过
更新 PRODUCT.md 和 PROGRESS.md
提交并推送代码到 main
在 main 分支上打版本标签
分别在 Windows 和 macOS 上打包
在 GitHub Releases 中上传两个平台的安装包
发布 Release
4. 平台适配要点（macOS）
路径分隔符：使用 os.path.join() 和 os.path.normpath()，避免硬编码 \ 或 /

FFmpeg 查找：除系统 PATH 外，支持 macOS 应用包内捆绑 FFmpeg

数据库路径：使用 Path.home() / ".coverpicker"，跨平台一致

PySide6 兼容性：确认 Qt 6.11.1 在 macOS 10.15.8 上的运行情况

打包配置：PyInstaller 生成 .app 包，包含必要资源
